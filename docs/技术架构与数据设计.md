# 技术架构与数据设计

## 1. 总体结构

应用采用 Flutter + Provider，按职责分为五层：

1. 页面和组件：负责交互、列表、阅读器和状态展示。
2. Controller：协调页面状态、数据库、网络和文件操作。
3. Service：实现 SQLite、API、目录授权、ZIP、缓存和简繁转换。
4. Model：定义漫画、章节、下载任务和最近观看等稳定数据结构。
5. 平台桥接：Android Kotlin 与 iOS Swift 处理系统目录选择、持久授权和设备身份。

启动依赖关系：

```text
LocalAppDatabase
├── AppearanceController
├── ReadingHistoryController
├── LibraryDatabase
│   └── LibraryController
├── FavoritesController
└── DownloadController

CopyClient
├── SessionController
├── LibraryController
├── FavoritesController
└── DownloadController
```

`main.dart` 只负责对象装配和初始化顺序，具体协议和页面逻辑不写在启动文件中。

## 2. 共享漫画库

### 2.1 文件结构

共享漫画库根目录必须能定位到 `拷贝漫画总索引.db`。漫画文件使用相对路径，
不在数据库中保存某台设备的绝对路径。

命名规则由 `lib/core/file_names.dart` 统一实现：

- 漫画目录：`漫画名 - 作者`
- 章节 ZIP：`漫画名 - 作者 - 章节名.zip`
- 汇总封面：`漫画名 - 作者 - 汇总.<扩展名>`

跨平台非法字符会替换为空格，尾部点号和空格会删除。

### 2.2 核心 SQLite

`拷贝漫画总索引.db` 是共享内容索引，核心表如下：

| 表 | 作用 |
| --- | --- |
| `comics` | 漫画 UUID、在线标识、名称、作者、目录、封面、来源和原始顺序 |
| `chapter_groups` | 单行本、连载、其他系列等章节分组 |
| `chapters` | 章节 UUID、标题、顺序、页数和 ZIP 相对路径 |
| `download_queue` | 与桌面下载器兼容的共享待下载章节索引 |

应用打开既有数据库时只校验核心表和必要列，不随意重建用户数据库。测试
`仅打开和查询既有漫画库不会改变索引数据库字节` 用于保护这个约束。

漫画来源 `source_kind`：

- `copy_manga`
- `dmzj`
- `both`

纯本地重建且无法对应在线漫画的项目使用稳定的 `local-...` 标识，在线批量扫描会
跳过它们。

### 2.3 外置库工作索引

SQLite 不直接在 iOS 安全作用域 URL 或 Android 文档树 URI 上工作。选择外置库
后，`LibraryLocator.databaseFileFor` 会：

1. 根据目录路径、数据库大小、头部和尾部字节计算稳定库 ID。
2. 在应用支持目录创建 `external_libraries/<library-id>`。
3. 第一次原子复制总索引和存在的 WAL。
4. 以后打开同一库时复用本机工作索引。

外置原始数据库因此保持不变。漫画文件仍按外置根目录的相对路径读取；正式下载也
写入当前外置漫画目录。

## 3. 本机状态数据库

`copy_manga_reader_local.db` 位于平台应用支持目录，使用 WAL 和 5 秒
`busy_timeout`。它不随漫画库搬运。

| 表 | 内容 |
| --- | --- |
| `recent_views` | 每部漫画最后观看章节、页码和时间 |
| `read_progress` | 每个章节的当前页和总页数 |
| `local_preferences` | 主题、深色模式、筛选、排序和并发设置 |
| `comic_details` | 简介、别名、状态、地区、题材等在线详情缓存 |
| `favorites_cache` | 当前漫画库对应的收藏缓存与顺序 |
| `download_tasks` | 正式下载任务、状态、进度和错误 |
| `search_index` | 漫画名与作者的简繁归一化索引 |

需要按漫画库隔离的表使用 `library_key`。`library_key` 来自实际打开的工作数据库
绝对路径，防止切换多个库时下载任务和收藏互相混淆。

旧版本曾放在共享库中的应用状态会只读迁移到本机库。迁移完成后新状态只写本机库。

## 4. 搜索设计

`ChineseSearchNormalizer` 载入内置 OpenCC 字符映射，生成原字形、简体和繁体
查询变体。

本地搜索：

1. 归一化漫画标题和作者。
2. 存入本机 `search_index`。
3. 查询时同时匹配原字形和转换字形。

在线搜索按查询变体依次请求，第一组非空结果即返回。网络响应只在内存中解析，不落
地为 JSON 文件。

## 5. API 分层

网络代码按变化频率拆分：

- `copy_api_protocol.dart`：版本、请求头、签名、路径和参数。
- `copy_api_transport.dart`：Dio、节点发现、测速、故障切换、令牌注入和错误。
- `copy_client.dart`：漫画、章节、收藏和账号业务对象解析。
- `copy_device_identity.dart`：平台设备身份转换。

页面不能直接拼 URL 或请求头。服务端调整协议时应先改 protocol 和 transport，
再用协议测试确认业务页面无需变化。

### 5.1 匿名与会员请求

默认 `requestResults` 的 `authenticated` 为 `false`。以下操作匿名执行：

- 搜索
- 漫画详情
- 章节目录
- 章节图片列表
- 图片获取
- 批量补缺扫描

只有资料和收藏等会员接口显式设置 `authenticated: true`。传输层只在这种情况下
加入 `authorization: Token ...`。

登录接口使用独立的最小请求头和表单编码；登录成功后必须再调用资料接口验证令牌。
验证失败会立即清除内存令牌。

### 5.2 节点发现和切换

内容节点通过 `network2` 动态发现并测速。自动模式选择最低延迟可用节点；手动模式
锁定用户指定节点。网络错误、无效 JSON、接口不支持或返回结构校验失败时，传输层
按候选节点顺序切换。

章节图片列表依次兼容当前章节接口、阅读接口和下载接口。任何候选返回空图片列表都
视为该候选失败，不会把空章节当成更新成功。

账号节点单独维护，因为国内、海外账号库可能不互通。

## 6. 在线阅读缓存

`OnlineChapterBook` 的流程：

1. 匿名取得章节图片 URL。
2. 根据章节 UUID 计算缓存目录。
3. 根据页号和 URL 哈希生成稳定缓存文件名。
4. 只请求当前页附近的图片。
5. 先写 `.part`，刷新后原子改名。
6. 同一页并发请求合并为同一个 Future。

缓存根位于系统临时目录 `copy_manga_online_cache`。它不生成 ZIP、不更新
`archive_relative_path`，系统可以在空间不足时清理。

## 7. 正式下载

`DownloadController` 的状态：

```text
queued → downloading → completed
                    ↘ failed
queued/downloading → paused
paused/failed → queued
```

每章内部使用可调工作线程并发下载图片。每页先写 `.part`，完成后改成实际图片
扩展名；全部页完成后才创建 `.partial` ZIP 并原子改名为最终 ZIP。

数据库进度是各页字节进度的平均值。全局暂停通过取消当前 Dio 请求、等待处理循环
结束，再持久化任务状态实现。

清空任务只删除本机 `download_tasks`，不删除 ZIP。

## 8. 阅读器

本地章节由 `ZipBook` 在后台 Isolate 解压到系统临时目录。关闭阅读器时删除展开
目录，不修改原 ZIP。

`ReaderController` 同时支持本地 `ZipBook` 和在线 `OnlineChapterBook`，
因此两种来源共用：

- 上下连续和左右单页
- 阅读位置
- 最近观看
- 沉浸工具栏
- 缩放和拖动

连续阅读使用两个 Sliver 列表，以保存页为锚点恢复前后内容，避免长漫画恢复位置时
先构建所有前置页面。可见页根据视口参考点更新进度。

`ZoomableViewport` 自行处理指针：

- 两指计算焦点和缩放比例。
- 放大后单指 X/Y 同时移动。
- 连续模式把超出视口的垂直位移交给外层滚动视图。
- 缩放期间锁定底层 PageView/ScrollView，避免手势竞争。

## 9. 平台桥接

### Android

`MainActivity.kt` 使用 `ACTION_OPEN_DOCUMENT_TREE` 选择目录并保存持久 URI 授权。
对于可直接访问的内部存储和可移动卷，桥接层解析为文件路径供 SQLite 与 ZIP 使用。

### iOS/iPadOS

`AppDelegate.swift` 使用系统目录选择器，保存 security-scoped bookmark，
恢复时调用 `startAccessingSecurityScopedResource`。切回默认库时停止访问并释放
授权。

两个平台都通过独立 MethodChannel 提供设备身份，失败时回退为无敏感信息的稳定
默认值。

## 10. 不变量

修改代码时必须保持：

1. 应用状态不新增到共享漫画索引。
2. 在线阅读不生成 ZIP、不标记已下载。
3. 正式下载只从明确的下载操作进入。
4. 匿名接口不携带会员令牌。
5. 外置原始 SQLite 不直接写入。
6. 文件路径写入数据库时使用漫画库相对路径。
7. 已下载 ZIP 不因清理任务而删除。
8. 既有数据库只读打开不会改变其字节。
9. 页面不硬编码 API URL、签名或协议参数。
10. 新版本必须通过静态检查、数据库、API、阅读器和下载回归测试。
