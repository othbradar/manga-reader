# 2026-10-27：3.0.9 协议复核、小说与收藏验收

适用版本：原版 APK `3.0.9`，阅读器 `0.5.1+33`。这是一份增量交接记录，配合
[原版 APK 逆向与协议迁移](原版APK逆向与协议迁移.md) §33–35 使用。
记录恢复方法、证据、排除路径、源码入口与验收边界，不保存用户密码、Token、设备实例值、
流量包、原始 APK 或反编译代码。既有样本继续只在被 Git 忽略的 `reverse_engineering/`。

## 1. 先明确问题所在层级

当时表现为阅读器账号功能异常，而原版新测试账号能收藏；之后用户确认主账号受限。
这些现象只能分别说明“某个原版会话可用”和“某个账号受限”，不能直接证明域名、签名或
密码编码哪个错误。响应“账号不存在”“服务暂时不可用”也不能当作根因。

分析从客户端开发者的数据流出发：

```text
Android 平台桥接 / 安装元数据
  → Dart 启动初始化：覆盖初始 extra
  → 业务函数：path、method、query、data
  → 公共 POST 包装：业务 data + 公共 extra
  → Dio 普通请求拦截器：extra → headers，补 query
  → HTTP 编码与服务器语义结果
```

只看路径字符串会漏掉参数；只看初始 Map 会拿到尚未覆盖的旧版本和测试渠道；只看 Dart
签名函数无法知道原生材料来源。因此必须把上下游串起来，最后再通过真实业务回查验收。
这不是为了读取原版账号数据：签名所需材料来自公开 APK 证书，不需要用户私钥或原版 Token。

## 2. 固化样本与证据分级

| 对象 | 指纹 |
| --- | --- |
| 用户提供/设备安装的 APK | SHA-256 `bdc96763c78bbc060a0f2f2c05024bb3379fad485be9843a82768f41c482194b` |
| 证书 | SHA-256 `1800b4b60e9fee73916860717b97a11d89ed6c643a923b9c36a9c7b868c04c52` |
| 证书公开摘要 | MD5 `3af08590311032efe0660550a0563a53` |
| 含桥接类的已加载 DEX | SHA-256 `2b953e66f336230eea7a3820315c471fede2aaace80c665cc30ef6e0b89b6c2b` |

本次的 ARM64 地址仅对应这个 `libapp.so`，不是下一版可套用的绝对地址。
以下结论按三层区分：

1. **静态/已加载代码证据**：AOT 指令、对象池、运行时 DEX、APK 证书。
2. **离线可重复验证**：独立 OpenSSL 向量、模拟 Dio 最终请求、SQLite/组件回归。
3. **真实服务验收**：匿名搜索/详情/章节/TXT，及用户登录后收藏写入与完整列表回查。

第 2 层通过不等于第 3 层必然接受；第 3 层一次通过也不是永不风控保证。

## 3. Java 层受壳影响时如何继续

原 APK 的 JADX 结果主要是壳；不能因此认定 Android 层没有签名材料。
Frida 16.7.19 附加失败，17.24.3 加载脚本连接关闭；无法确定是 Android 17 兼容性还是
加固检测，不把原因猜测写成定论，也不继续反复注入。`/proc/<pid>/mem` 只读访问亦被拒绝。

替代方法为 `tool/reverse_apk_code.c`：在已具备调试权限的设备上用 `process_vm_readv`
仅获取经过 DEX header 验证的已加载代码容器。工具校验包名，限制映射类型和 DEX
magic/header/大小/端序/边界；不是通用内存、堆或账号数据导出工具。
9 个代码容器共 61,626,600 字节，筛选桥接字符串后只反编译相关 DEX。

复现前先确认设备、包名和当次 PID；具体命令见主文档 §33.3。JADX 有 7 处其他类错误，
但相关 MainActivity 方法完整；不能因为存在错误就丢掉有效证据，也不能把整个产物称为完整反编译。
临时 UID 网络隔离、调试服务、端口转发结束时均恢复，未清原版账号数据。

## 4. 从桥接返回值恢复签名

通道 `com.hotmangas.plugins/utils` 中：

- `getUmengString → MainActivity.i() → GET_SIGNATURES → signatures[0].toByteArray()`。
- `MainActivity.j(byte[])` 对证书字节做 MD5，逐字节补零，输出小写 hex。
- `getUmengChannel → MainActivity.h()` 返回 `copyApp`。

`getUmengString` 不是 Umeng 私钥/设备 OAID；用 `apksigner verify --print-certs` 的
证书 MD5 可以独立核对。不要混淆公开证书摘要与签名私钥。

| AOT 锚点 | 本次确认的含义 |
| --- | --- |
| `0xa84f24 → 0xa101e4` | 桥接结果流入两条 setter |
| `0xa10484` | 保存 extra.tapString |
| `0xa10414 / 0xa10378` | UTF-8 + MD5，保存 extra.umString |
| `0xa350ac / 0xa35124 → 0x308ac4` | 取 tapString，构造 HMAC-SHA256 时间签名 |
| `0xa84e8c / 0xa100a4 / 0xa1014c` | 原生渠道覆盖 source |

签名公式：

```text
tapString = lowercaseHex(MD5(APK signing certificate bytes))
umString  = lowercaseHex(MD5(UTF8(tapString)))
timestamp = decimal Unix seconds, renewed per request
signature = lowercaseHex(HMAC-SHA256(key=UTF8(tapString), message=UTF8(timestamp)))
```

独立向量，不使用真实身份：

```bash
printf '%s' 3af08590311032efe0660550a0563a53 | openssl dgst -md5
# b4c89ca4104ea9a97750314d791520ac
printf '%s' 1785328496 | openssl dgst -sha256 -hmac 3af08590311032efe0660550a0563a53
# 48f772e76c034d8281f1cab1bc52f5d25597ad1c6ed44642780b5d7e94954471
```

实现集中在 `CopyRequestProtocol`；测试不能仅断言摘要非空，必须对比精确字节/hex。

## 5. 区分初始 extra、启动覆盖和最终请求

`0x309d9c` 是初始 extra，不是可直接照抄的 headers。
字段定位：`_Gw._Yzb +0xc` 为 headers，`_Gw.CCe +0x2c` 为 extra，
`_Fw.jjb +0x4c` 为 queryParameters。需要追踪 setter 到普通请求拦截器。

| 参数 | 初值陷阱 | 实际使用 |
| --- | --- | --- |
| version | `3.0.0` | 启动覆盖为 `3.0.9` |
| userAgent | 空 | `COPY/3.0.9` |
| source | `#utm_source=FlutterTest` | 原生回调 `copyApp` |
| webp | `0` | 启动覆盖为 `1` |
| platform | 字符串/整数混淆 | header/form `3` 字符串，query 整数 3 |
| region | 把 `-0800` 误当线路 | 国内 0、海外 1；日期后缀不是 region |
| dt | 每次请求重算 | 启动墙钟前 19 位 + `-0800` parse；header yyyy.MM.dd |
| timestamp | 复用 dt | 每个请求当前 Unix 秒 |
| device | Android ID 或型号猜测 | 原版 extra.androidId 实际来自 Build.ID |
| deviceInfo | 只用型号 | Build.MODEL + `-` + Build.DEVICE |
| pseudoID | 复制原版实例值 | 阅读器自己生成并持久化 16 位 base62 |
| Accept-Language | 自行补语言常量 | 普通拦截器缺值时为空字符串 |

Android 字段证据：`0x515654` 读取 device/id/model；构造器 `0x5160b8` 分别落在
`+0xf/+0x13/+0x17`；启动 `0xab7e44` 把 id 传给 androidId setter，`0xab7e88` 拼 model-device。
设备标识只在本机 `device_identity` 表，应用数据导出不包含该表，跨机导入不覆盖当前安装身份。
身份初始化失败会拦截 API 请求，不编造零值；本地阅读仍然可用。

最终 header 及完整字段表见[接口维护 §10](拷贝漫画接口维护.md#10-当前-309-协议基线)。
extra 的 `tapString/androidId/userAgent/isGoogle/buildTime` 不应被直接全部塞进 headers。
iOS/macOS 使用各平台自己的元数据，不伪装成某台真实安卓设备；本次没有原版 iOS 抓包证据。

## 6. 登录与 POST 编码的关键修正

`0xa586f8` 确认 salt 为 `Random.secure().nextInt(9999).toString()`，范围 0–9998，
不是固定 1729，也不是保留前导零的四位数字串。
密码业务字段为 `Base64(UTF8(password + "-" + salt))`。

公共 POST 路径 `0xa36098 → 0xa3617c → 0xa36278`，其中
`0xa361ec..0xa36228` 执行 `data.addAll(options.extra)`。这说明只照抄登录/收藏
业务字段仍不完整，必须合并初始化后的公共 extra，并用 `application/x-www-form-urlencoded`。
GET 不发送这份 form；API query 均补 platform=3。

登录 header 与 form 均为空 `Token `，不会带旧登录用户 Token；资料和收藏才带当前 Token。
测试通过 Dio adapter 读取实际 encoded body，核验布尔、日期、空 Token 与 URL 编码，而不只看
调用前的 Dart Map。生产日志不记录原始 form、密码、编码密码、Token 或设备标识。

## 7. 逐功能协议与原版差异

以下路径统一以 `/api/v3` 开头，内容请求即使已登录也不附用户 Token。

| 功能 | 方法/路径 | 核验要点 |
| --- | --- | --- |
| 登录 | POST `/login` | 表单、随机 salt、公共 extra；成功后 profile 验证 |
| 资料 | GET `/member/info` | 当前账号节点和 Token |
| 漫画收藏列表 | GET `/member/collect/comics` | limit=18、offset、free_type=1、ordering |
| 小说收藏列表 | GET `/member/collect/books` | 同上；`0x4b08f8..0x4b09b0` |
| 漫画收藏变更 | POST `/member/collect/comic` | comic_id、is_collect=1/0；`0xa91554..0xa915e0` |
| 小说收藏变更 | POST `/member/collect/book` | book_id、is_collect=1/0；`0xa93480..0xa93514` |
| 漫画/小说搜索 | GET `/search/comic`、`/search/books` | q、q_type、limit、offset；list 结构 |
| 漫画/小说详情 | GET `/comic2/{path}`、`/book/{path}` | path_word/uuid；in_mainland、request_id |
| 漫画目录 | GET `/comic/{path}/group/{group}/chapters` | 分组及分页完整性 |
| 漫画阅读/ZIP 地址 | GET `/comic/{path}/chapter2/{id}` | 图片列表非空且身份匹配 |
| 小说卷目录 | GET `/book/{path}/volumes` | 不加业务分页/ordering；`0x5d6f8c → 0xa7d0ac` |
| 小说卷内容 | GET `/book/{path}/volume/{id}` | volume.id、book_path_word、txt_addr/encoding、contents |
| 发现/测速 | GET `/system/network2` | 同一公共签名、匿名状态、语义验证 |
| 图像/TXT CDN | GET 返回的资源 URL | 独立连接池，不携 API、设备或账号头 |

小说详情参数的调用证据为 `0x5d685c..0x5d68d8`。卷列表不等于收藏列表，不可通用套分页。
服务声明 total 大于实际 list，或返回错误卷 ID/书籍 path 时都保留本地旧目录并报错。

原版 `chapter2download` 匿名实际返回 401。按用户要求，本项目继续获取匿名阅读
`chapter2` 图片后保存 ZIP，不调用登录下载专用接口。这个行为差异是产品约定，不能以后误改，
也不能把它描述为“与原版所有功能逐字节相同”。

## 8. 账号与匿名请求的调度边界

`CopyApiTransport` 按明确白名单分类，不靠路径包含 member 的模糊匹配：

- profile、漫画/小说收藏列表与写入口才要求 Token；登录不带旧 Token。
- 分类与 HTTP 方法不符，在任何网络 I/O 前失败。
- 账号通道串行，前一次完成后至少间隔 1 秒；相同会话/path/query 的在途 GET 合并。
- 账号只用选定国内候选首项，不在 POST 超时、坏 JSON、404/503 后自动换节点重发。
- 账号 POST 不跟随重定向；429 尊重服务端 Retry-After；明确限制停止当前会话后续账号操作。
- 切换账号时，排队请求检查 token revision，旧请求不能借用新账号 Token 继续执行。
- 匿名请求仍可切换语义失效节点；CDN 并发不等于账号并发。

国内/海外账号可能不互通是用户实测的重要线索，但不能从客户端证实服务端数据库架构。
保留独立账号节点选择，不因海外内容测速快就把账号迁过去。
上述串行、限速和停止重放是阅读器保护策略，不是从原版证明的相同调度算法。

## 9. 收藏从按钮到最终确认

共同组件 `FavoriteButton` 仅管理交互，不拼 API 字段。两种详情页都使用它：

1. 未登录打开登录页；登录后重新读状态。
2. 当前会话/书库的列表未验证时先同步；确定是否已收藏后才允许写入。
3. 已是目标状态则跳过写入；点击“已收藏”先确认取消，不影响本地下载。
4. 一次写入后全量读回，对比 UUID 才显示成功；请求期间禁重复点击。
5. 不确定错误后按钮变为“重试收藏状态”，下一次仅回读，不直接重放 POST。
6. 账号/书库/作品变化时旧异步结果无效；本地无在线 ID 的作品不显示线上收藏按钮。

控制器为 `FavoritesController`、`NovelController`，HTTP 客户端负责业务 payload。
收藏列表按 total/offset 取完，提前空页、缺 list 或反复同一页不能覆盖原缓存。

批量入口为“收藏 → 小说 → 更多 → 收藏本地已匹配小说”。它读取整个库，
不受当前搜索/筛选影响；仅选择有效在线 UUID/path、已有下载卷且未收藏的作品。
逐本添加，首笔失败就停止，保留失败记录；用户主动继续时先重读列表，避免重复写入。
最终回查集合，结果不能仅凭 HTTP 200 或进度条到 100% 判断。

## 10. 小说数据和迁移边界

小说不是塞进漫画表，也不是每部一个 JSON 索引。

```text
整理后的库根/
├── 漫画/
│   └── 拷贝漫画总索引.db
└── 小说/
    └── 小说名 - 作者/
        ├── 分卷或章节.txt
        ├── 封面图片
        └── 卷内插图（具体相对路径见数据库）
```

共享索引新增表定义在 `assets/sql/novel_library.sql`：`novels`、`novel_volumes`、
`novel_sections`、`novel_import_sources`。不重建原 comics/chapters 表。
小说路径相对整个库根，必须落在同级 `小说/` 内；不能按漫画目录来拼。
`source_kind/library_order/title_sort_key` 在索引中保存，筛选/排序不靠页面硬编码。

`NovelStore` 管文件/共享表，`novel_text.dart` 管文本解码和行处理，`NovelController`
管同步、下载、收藏与状态。阅读进度、下载任务、收藏缓存分别在本机 `novel_progress`、
`novel_tasks`、`novel_favorites`，可携式应用数据导入会重映射库标识并暂停任务。
账号凭据和当前安装身份不进入共享内容库或可携式应用数据文件。

外置盘仍使用本机工作索引机制。给别的设备拷贝时，内容需要漫画与小说两个同级目录，
且总索引要是含小说表的版本；不要拿旧纯漫画索引覆盖新库。
无法在线匹配的小说转换为本地格式继续可读，不强行匹配同名不同作者作品。
`sync_novels.py` 的旧网络入口已经停用，只保留本地导入转换和离线测试，不能绕过新共享请求层。

## 11. 实测结果与验收边界

### 匿名链路（0.5.0+32）

直连国内引导节点一次超时后，显式用 `127.0.0.1:7890` 做少量匿名检查；未改系统/Git代理。
`network2` 从 `api.copy202602.com` 返回 `api.copy202601.com`。
漫画/小说搜索及详情成功；异世界叔叔默认目录首批 100、total=119，首章 15 图，
首图 194398 字节且 WebP 魔数正确。无职转生返回 34/34 卷，首卷 34 项内容，
TXT 333415 字节且可按 UTF-8 解码。未批量拉取正文或写原库。

### 用户会话和收藏（0.5.0+32 → 0.5.1+33）

- 用户亲自登录 Mac 阅读器；单本小说《0能者九條湊》添加后列表 4 → 5。
- 漫画《12歲》添加后列表 430 → 431，详情按钮“已收藏”。
- 本地小说 291 部，286 部有在线匹配；其中 3 部已在收藏，批量新增 283，失败 0。
- 服务端完整分页回读 288 部；只读按 UUID 集合对照本地 286 部，全部包含，缺失 0。
- 另外两部原有收藏《我們的重製人生》《戰鬥妖精雪風》保留。
- 5 部纯本地小说未发送线上收藏，作品文件及共享索引未因收藏变更而改动。
- 用户已确认 Android 小说阅读正常；0.5.1+33 本次收藏写入实测发生在 Mac。

### 仍不可宣称的结论

没有原版 iOS 原生元数据逐项核验；没有覆盖广告 request_id 完整生命周期，当前按无广告空值。
本次不是全站/所有账号/所有节点兼容性测试，没有证明既有限制解除或永不风控。
两种 IPA 编译、结构与 ID 检查通过，不等于本次都做了 iPhone/iPad 实机覆盖安装。
取消收藏通过 mock 与组件测试，不为验收去删用户原有收藏。

## 12. 下次 APK 更新的最短复查路径

| 现象 | 优先看 | 不应先做 |
| --- | --- | --- |
| 匿名全失败 | network2、公共启动参数、拦截器、设备初始化 | 给匿名接口加 Token |
| 登录账号不存在 | 同区原版对照、form 最终字节、salt、启动覆盖 | 多账号/多节点连续重放密码 |
| 可读收藏但写失败 | 单数路径、UUID字段、POST公共extra、账号限制 | 循环批量提交 |
| 详情成功但目录空 | 请求 path、分组、total/list、卷接口分页差异 | 清空旧目录再刷新 |
| 章节无图 | chapter2 响应身份/图片字段、内容节点 | 改用登录专用下载接口 |
| 只有图片/TXT失败 | 独立 CDN、过期URL、魔数/编码 | 把 API/Token 头加给 CDN |
| SDK/壳使 JADX 缺类 | 已加载桥接代码、AOT 字符串调用链 | 盲目补猜常量 |

执行顺序：新样本 hash/证书 → diff 稳定字面量 → 原生材料 → 启动覆盖 →
业务函数/公共包装/最终请求 → 离线向量和矩阵 → 少量匿名链路 → 用户明确授权的单笔账号操作
及回查。不要一开始就用整库收藏测试协议。

Blutter 函数 size=-1 时，`tool/inspect_copy_aot.py` 用 llvm-objdump 辅助标注对象池：
